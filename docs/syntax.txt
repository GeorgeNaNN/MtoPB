MtoPB 支持的 Markdown 语法总览

更新时间：2026-11-25

说明：
1. 本文按三个部分说明：0.29-GFM、扩展语法、自定义语法。
2. “0.29-GFM”部分列出项目支持的常用 CommonMark 与 GFM 0.29 写法。已知差异见该部分末尾。
3. “扩展语法”表示通过第三方 markdown-it 插件增加、且不属于 GFM 0.29 规范的语法。
4. “自定义语法”表示 MtoPB 自己增加的解析、路径处理、渲染或资源能力。
5. 原始 HTML 的嵌入写法和任务列表归入“0.29-GFM”；项目额外允许的 CSS、JavaScript 和本地 HTML 资源处理归入“自定义语法”。

============================================================
一、0.29-GFM
============================================================

规范名称：GitHub Flavored Markdown Spec

规范版本：0.29-gfm（2019-04-06）

官方规范网址：

https://github.github.com/gfm/

本项目使用 markdown-it 解析 Markdown，支持下列常用 CommonMark 和 GFM 写法。该列表不代表项目完全符合 GFM 0.29。


1. 标题

ATX 标题：

# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题

Setext 标题：

Setext 一级标题
===

Setext 二级标题
---


2. 普通段落

这是第一个段落。

这是第二个段落。


3. 软换行

这是第一行，
这一行通常仍属于同一个段落。


4. 强制换行

行尾两个空格：

这一行末尾有两个空格。  
这一行会出现在下一行。

行尾反斜杠：

这一行末尾使用反斜杠。\
这一行会出现在下一行。


5. 强调文字

**粗体文字**

*斜体文字*

***粗斜体文字***


6. 行内代码

`const value = 42;`


7. 围栏代码块

三个反引号：

```javascript
console.log("MtoPB");
```

三个波浪线：

~~~text
代码块内容
~~~


8. 缩进代码块

四空格缩进：

    indented code
    second line


9. 引用块

> 一级引用

> > 二级嵌套引用


10. 无序列表

- 第一项
- 第二项
- 第三项

也支持：

+ 第一项
+ 第二项


11. 有序列表

1. 第一项
2. 第二项
3. 第三项

也支持：

1) 第一项
2) 第二项


12. 嵌套列表

- 父项
  1. 子项一
  2. 子项二
- 另一个父项


13. 行内链接

[OpenAI](https://openai.com)


14. 引用式链接

[OpenAI][openai]

[openai]: https://openai.com


15. 尖括号自动链接

<https://example.com>


16. GFM 自动链接字面量

不需要尖括号，以下内容会自动转换为链接：

https://example.com

http://example.com

www.example.com

tester@example.com


17. 图片

![图片说明](图片.png)

含空格的路径可用尖括号包住，图片标题建议使用双引号或单引号：

![图片说明](<我的 图片.png> "图片标题")


18. 分隔线

---

***

___


19. 反斜杠转义

\*不是斜体\*

\# 不是标题

\\ 显示反斜杠


20. HTML 字符实体

&copy;

&amp;

&#169;


21. GFM 表格

| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| A | B | C |
| 1 | 2 | 3 |


22. GFM 删除线

~~删除文字~~

~删除文字~

GFM 0.29 支持单波浪线和双波浪线，开头和结尾使用相同数量的波浪线。

三个及以上连续波浪线不会形成删除线，例如：

~~~文字~~~


23. 原始 HTML

行内示例：这是 <strong>HTML 加粗</strong>。

块级示例：

<div>
这是 HTML 块。
</div>


24. GFM 任务列表

- [ ] 未完成任务
- [x] 已完成任务
- [X] 已完成任务，大写 X 也有效

MtoPB 通过 markdown-it-task-lists 提供此功能。任务标记后请使用普通空格再写正文。PDF 中的复选框是静态的。


与 0.29-GFM 的兼容说明：

1. 裸链接使用 markdown-it 的 linkify 识别，范围比 GFM 0.29 更宽，例如也会识别 example.com 和 ftp://example.com。
2. 项目在合并时会改写本地图片路径，圆括号形式的图片标题可能被当成路径的一部分。请用双引号或单引号写图片标题。
3. 项目未启用 GFM 的 tagfilter，因此不会因该规则过滤 style、script 等标签。CSS 和 JavaScript 的用法见“自定义语法”。
4. GFM 允许任务标记使用其他空白字符，MtoPB 使用的插件要求普通空格，例如不识别标记后直接跟制表符的写法。

============================================================
二、扩展语法
============================================================

本部分语法由 markdown-it 插件提供，不属于 GFM 0.29 规范。


1. KaTeX 行内公式

质能方程为 $E = mc^2$。


2. KaTeX 块级公式

$$
a^2 + b^2 = c^2
$$

公式语法错误不会中断整个转换，会显示错误公式。


3. 等号高亮

==高亮文字==


4. 自动标题锚点

每个 Markdown 标题会自动生成唯一 ID。

相同标题会自动追加 -2、-3 等后缀。

例如：

## 测试标题

可以这样跳转：

[跳转到测试标题](#测试标题)

自动锚点同时用于目录和 PDF 书签。


5. note 提示框

:::note 注意
这是 note 内容
:::


6. tip 提示框

:::tip 提示
这是 tip 内容
:::


7. warning 提示框

:::warning 警告
这是 warning 内容
:::


8. danger 提示框

:::danger 危险
这是 danger 内容
:::


9. theorem 环境

:::theorem 勾股定理
直角三角形两直角边平方和等于斜边平方
:::


10. definition 环境

:::definition 质数
只能被 1 和自身整除的大于 1 的自然数
:::


11. example 环境

:::example 示例
这是 example 环境
:::


12. exercise 环境

:::exercise 练习
请计算 $1 + 1$
:::


13. GitHub Alerts

> [!NOTE]
> 注意内容

> [!TIP]
> 提示内容

> [!IMPORTANT]
> 重要内容

> [!WARNING]
> 警告内容

> [!CAUTION]
> 危险内容

默认标题会显示为：

NOTE      注意
TIP       提示
IMPORTANT 重要
WARNING   警告
CAUTION   危险

GitHub Alerts 是 GitHub 扩展，不属于 GFM 核心规范。


============================================================
三、自定义语法
============================================================

本部分是 MtoPB 自己增加的行为，或不属于 Markdown/GFM 本身、但项目明确允许的能力。HTML、CSS、JavaScript 及外部资源均归入此部分。


1. 自定义图片宽度和高度

![说明|400x250](图片.png)

400 和 250 的单位是像素。


2. 自定义图片宽度

![说明|400](图片.png)

只指定宽度，高度按图片比例自动计算。


3. 图片题注

![图片说明](图片.png "这是图片下方的题注")

单独成段且段内只有一张 Markdown 图片时，会生成 figure；图片带标题时，标题显示为图注。行内图片不会自动生成图注。


4. 带空格图片路径自动修复

不需要手写尖括号：

![说明](C:\Users\Name\我的 图片\封面.png)

项目会自动转换为：

![说明](<C:\Users\Name\我的 图片\封面.png>)

代码块内部的路径不会被自动修改。


5. 强制分页

\pagebreak

或者：

\newpage

强制分页命令必须单独占一个段落。


6. 手动命名锚点

<a id="manual-anchor"></a>

然后可以跳转：

[跳转到手动锚点](#manual-anchor)


7. HTML 中的本地资源

<img src="./我的 图片.png" alt="本地图片" width="120">

支持的 HTML 资源属性可用带引号的本地路径。合并时会按源 Markdown 文件所在目录解析相对路径。实际显示和打印效果由 Chromium 决定。


8. 行内 CSS

<span style="color: red; font-weight: bold;">红色粗体文字</span>


9. 独立 style 块

<style>
.custom-box {
  color: red;
  border: 1px solid #000;
}
</style>

<div class="custom-box">内容</div>

style 块会参与 HTML 排版和最终 PDF 渲染。


10. 外部 CSS 文件

<link rel="stylesheet" href="./自定义.css">

项目会把本地相对路径解析为可访问的文件路径。


11. 独立 script 块

<script>
document.querySelector(".custom-box").textContent = "脚本修改后的内容";
</script>

JavaScript 会在 Chromium 加载 HTML 时执行，因此可以修改 DOM、增加元素或改变样式。


12. 外部 JavaScript 文件

<script src="./自定义.js"></script>


13. JavaScript 的作用范围

JavaScript 不属于 Markdown/GFM，也不会保留在最终 PDF 中。

脚本可在打印前修改页面内容或样式。应检查这些变化是否出现在 PDF 中；异步请求或长定时器不保证在打印前完成。


14. 外链自动属性

由 Markdown 渲染器生成的 http:// 或 https:// 链接会自动添加以下 HTML 属性：

target="_blank"

rel="noopener noreferrer"


15. 代码语法高亮

围栏代码块支持 highlight.js 高亮。

使用方式：

```python
def hello():
    print("hello")
```

支持 highlight.js 内置的常见语言。

无法识别语言名称时，仍会显示为普通代码块。


16. 代码块行号

代码行号可通过软件配置开启或关闭。

行号是独立渲染功能，不属于 Markdown 语法。


17. Markdown 标题生成目录

主目录收录不超过所选目录层级的 Markdown 标题。

HTML 的 h1 到 h6 不会进入目录。


18. 目录最大层级

软件支持 1 到 6 级目录。

目录层级会同步用于 PDF 书签。


19. 页眉标题

正文页的页眉标题根据该页所属的一级 Markdown 标题生成。


20. PDF 页码

按“页码计数规则”从封面、目录或正文开始计数。这是导出设置，不需要额外的 Markdown 指令。


21. 图片路径资源解析

Markdown 图片和 HTML 图片都会解析本地资源路径。

本地图片必须存在，否则转换检查会报错。


22. 文件格式

项目接受：

.md

.markdown


============================================================
结束
============================================================

以上三部分互不重复：

1. 0.29-GFM：已支持的常用 CommonMark 和 GFM 0.29 写法及已知差异。
2. 扩展语法：插件提供的数学公式、高亮、提示框、锚点和 GitHub Alerts。
3. 自定义语法：图片尺寸和图注、分页、手动锚点、CSS 和 JavaScript、本地资源、代码高亮和目录生成等 MtoPB 行为。
